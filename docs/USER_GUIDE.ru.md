# XiaomiHome - Руководство пользователя

![XiaomiHome Icon](../static/XiaomiHome.png "Плагин XiaomiHome")

## Назначение

`XiaomiHome` интегрирует Xiaomi Zigbee Gateway и дочерние устройства в osysHome через multicast UDP (`224.0.0.50:9898`).

Модуль нужен, чтобы:

- автоматически обнаруживать шлюз и Zigbee-устройства по сетевому трафику;
- хранить локальный реестр устройств и параметров;
- связывать параметры Xiaomi с `Object.property` и `Object.method`;
- отправлять команды обратно в Xiaomi при изменении свойств osysHome.

> [!IMPORTANT]
> Интеграция двусторонняя: Xiaomi -> osysHome (телеметрия/события) и osysHome -> Xiaomi (управление).

---

## Что получает пользователь

| Возможность | Что делает |
| --- | --- |
| Автообнаружение | Создает устройства автоматически из входящих пакетов (`sid`, `model`, token, IP) |
| Реестр команд | Создает/обновляет записи команд (`xicommands`) по входящим данным |
| Связи со свойствами | Записывает значения в связанные свойства osysHome |
| Связи с методами | Вызывает связанные методы osysHome при событиях |
| Обратное управление | Преобразует изменения свойств osysHome в Xiaomi-пакеты `write` |
| Поиск | Возвращает связанные команды через глобальный поиск (`search`) |

## Обзор интерфейса

Страница администрирования:

```text
/admin/XiaomiHome
```

Основные действия:

1. Открыть редактирование устройства (`?op=edit&device=<id>`)
2. Удалить устройство (`?op=delete&device=<id>`)
3. Настроить связи команд (объект/свойство/метод)
4. Сохранить изменения и ключ шлюза

### Колонки списка устройств

| Колонка | Значение |
| --- | --- |
| Title | Удобное имя устройства |
| Type | Модель Xiaomi (`gateway`, `plug`, `sensor_ht`, `magnet`, ...) |
| SID | Xiaomi `sid` |
| IP | IP шлюза для отправки управляющих пакетов |
| Updated | Время последнего обновления из входящих пакетов |

## Чек-лист быстрого запуска

- [ ] Откройте `/admin/XiaomiHome`.
- [ ] Дождитесь трафика автообнаружения (модуль отправляет `{"cmd":"whois"}` при старте).
- [ ] Откройте устройство-шлюз и задайте `Key` (`gate_key`).
- [ ] Для нужных устройств свяжите команды с объектами/свойствами/методами osysHome.
- [ ] Сохраните изменения.
- [ ] Проверьте, что входящие значения обновляют свойства.
- [ ] Проверьте обратное управление, изменив связанное свойство osysHome.

## Как работает обнаружение

Обычно вручную добавлять устройства не нужно. Модуль создает их сам, когда получает пакет Xiaomi с `sid`.

Автоматически заполняются:

- `sid`
- `model` -> `type`
- автозаголовок (`<Model> <YYYY-MM-DD>`)
- `gate_ip`
- `token` (если передан)

Для некоторых типов создаются команды по умолчанию:

| Тип устройства | Автосоздаваемые команды |
| --- | --- |
| `gateway` | `ringtone` |
| `curtain` | `curtain_status` |

> [!TIP]
> Если обратное управление не работает, сначала проверьте, что `Key` заполнен у шлюза с тем же `gate_ip`.

## Привязка команд к объектам osysHome

В редакторе устройства каждая команда может иметь:

- `Linked object`
- `Linked property`
- `Linked method`

### Связь со свойством

При приходе нового значения Xiaomi модуль пишет его в:

```text
Object.property
```

### Связь с методом

При приходе нового значения Xiaomi модуль может вызвать:

```text
Object.method
```

Метод получает полный декодированный payload пакета Xiaomi.

### Типовые примеры

| Команда Xiaomi | Цель связи | Эффект |
| --- | --- | --- |
| `temperature` | `Climate.outdoor_temp` | Синхронизация температуры |
| `humidity` | `Climate.outdoor_humidity` | Синхронизация влажности |
| `motion` | `Security.onMotion` (method) | Запуск логики движения |
| `leak` | `Safety.waterLeak` (method) | Запуск аварийной логики |
| `status` | `Door.contact` | Обновление статуса датчика |

## Основные входящие параметры

Модуль динамически создает команды из пакетов Xiaomi.

Часто встречающиеся параметры:

| Параметр | Типичный источник | Нормализация |
| --- | --- | --- |
| `temperature` | датчик t/h | делится на `100`, округляется до 2 знаков |
| `humidity` | датчик t/h | делится на `100`, округляется до 2 знаков |
| `pressure_kpa` | датчики с давлением | `pressure / 1000` |
| `pressure_mm` | датчики с давлением | перевод kPa в мм рт. ст. |
| `lux` / `illumination` | датчики освещенности | сохраняется как есть |
| `voltage` | батарейные устройства | mV -> V |
| `battery_level` | батарейные устройства | оценка `%` по mV |
| `motion` / `no_motion` | датчик движения | событийные значения |
| `channel_0`, `channel_1` | выключатели/реле | нормализация в `1/0` |
| `rgb`, `brightness` | подсветка шлюза | вычисляется из integer `rgb` |

## Обратное управление из osysHome

Когда в osysHome меняется свойство, `XiaomiHome` ищет связанные команды и отправляет пакет `write`.

Поддерживаются:

- `status` для розеток (`plug`, `ctrl_86plug.aq1`)
- `channel_0`, `channel_1` для реле/выключателей
- `curtain_level` (`0..100`)
- `curtain_status` (`open`, `close`, `stop`, `auto`)
- `brightness` и `rgb` для света шлюза
- `ringtone` для звука шлюза (`mid[,vol]` или `stop`)

### Пример управления цветом

Для команды `rgb` ожидается hex-цвет:

```text
#DA690A
```

Для `brightness` значение используется как старший байт в Xiaomi `rgb` payload.

## Диагностика и типовые проблемы

### Устройства не появляются

Проверьте:

- сервер получает multicast UDP на порту `9898`;
- циклическая задача модуля активна;
- на шлюзе Xiaomi включен LAN protocol.

### Значения приходят, но связи не срабатывают

Проверьте:

- у команды заполнен `Linked object` и `Linked property` или `Linked method`;
- выбранный объект/элемент действительно существует в osysHome;
- изменения сохранены в редакторе устройства.

### Обратное управление не влияет на устройство

Проверьте:

- у шлюза заполнен корректный `Key`, и токен свежий;
- шлюз и дочернее устройство имеют одинаковый `gate_ip`;
- используется команда из поддерживаемых для `write`.

> [!WARNING]
> Без корректной подписи (`gate_key` + `token`) шлюз Xiaomi отклоняет управляющие команды.

## Примечания и ограничения

- Устройства создаются по событиям из сети, отдельного мастера discovery нет.
- Некоторые команды событийные и могут вызывать метод повторно даже при том же значении.
- В UI есть удаление команд, но во фронтенде есть опечатка в локальном удалении из массива; после удаления может понадобиться обновить страницу.
- При таймауте входящих данных (`60s`) модуль переподключает сокет автоматически.
